OpenCode Coach automatically turns historical OpenCode sessions into an overview of recurring coaching patterns, their frequency, changes over time, and practical next steps. Individual sessions are optional evidence behind the overview. The interface groups Dashboard and Timeline under Observe, Output and Patterns under Measure, and Anti-Patterns and Context Health under Improve, with shared provider and project filters. Compact layouts use a horizontal navigation menu.

The plugin reads the database on the selected Paseo host in read-only mode. It recognizes V2 sessions and older SQLite databases. A database containing both uses V2 to avoid counting migrated sessions twice. No OpenCode server, VS Code extension, API key, or language model service is required.

Paseo 0.15.3 or later is required. The daemon needs Node's built-in SQLite support or the sqlite3 executable on its PATH. SQLite fallback was tested on macOS. Other operating systems have not been tested in a live host.

Provider settings let you enable, disable, select, or hide registered adapters and configure database paths. Discovery checks standard OpenCode data directories by default. An explicit path list replaces discovery. Only the OpenCode adapter is included; contributors can add other providers through the documented adapter contract.

The overview covers every matching session in the selected database and date window. It shows the three most frequent coaching priorities, counts and percentages, earlier/later period comparisons, a 14-day activity chart, and usage totals. Large histories are analyzed in the background with visible progress and warnings for unreadable or incomplete sessions. Results are provisional until analysis finishes. History supports date windows, a searchable multi-selection of existing Paseo projects, and optional pagination for individual-session evidence. Coaching is deterministic and heuristic. A logged test command is evidence that verification was attempted, not proof it passed. Sessions are read in small blocks, up to 100000 messages and 20000 legacy content parts, with visible warnings for incomplete, oversized or invalid records.

Analysis runs on the daemon host. Up to six overview jobs and 1000 normalized reports are held in memory. Derived reports are also saved in a protected local disk cache and reused across plugin reloads, daemon restarts and date-window changes; full conversations are not persisted. Only new or changed sessions are reimported after a metadata scan. Disabling a provider stops its background analysis before the next session read. Authorized Paseo clients receive session titles, directories, metrics, findings, and evidence IDs through Paseo's connection. The plugin has no outbound analytics or model requests, does not execute recorded commands, and does not modify session databases. As a trusted Paseo plugin, its code runs with the daemon's normal filesystem permissions.

Patterns includes a session-start heatmap, calendar activity and project breakdown. Output shows recorded token/model/edit data; it does not estimate generated code lines. Context Health reports session compaction and long-session signals, not repository instruction-file audits. Screenshot galleries and model-backed learning or skill-discovery features are not included.

German and English are available with saved language selection. The chosen time window, project selection and per-page session origin are saved on the host. Dashboard and Anti-Patterns default to human-led main sessions; Output, Patterns, Timeline and Context Health include delegated sessions. Project and workspace names from Paseo are shown alongside session labels.

Anti-pattern info icons explain each rule’s detection criteria and limits on hover, focus or click. Language selection lives in Settings. Project selection includes the project’s associated worktrees.

Date windows select sessions with message activity during the period, including older sessions resumed today. Metrics and rules use only messages inside the window. Timestamped rule features are cached locally, so switching periods does not import unchanged sessions again. Older aggregate-only cache entries need one local upgrade.

The Timeline groups sessions by workspace, with exactly one compact activity track per workspace and shared date/time markers across days. Hover, focus or click shows one session's title, time span, origin and project/workspace inline below the track. Analysis expands below its action inside the workspace card. Overlapping sessions remain reachable through small previous/next arrows beside the session title. The track displays the current paginated history page and includes idle time.

Numbered Timeline pages contain complete workspace groups with a saved page size of 5, 10 or 25 workspaces. The footer shows the exact workspace range and total; session totals are separate. A workspace is never split across pages.
