OpenCode Coach automatically turns historical OpenCode sessions into an overview of recurring coaching patterns, their frequency, changes over time, and practical next steps. Individual sessions are optional evidence behind the overview.

The plugin reads the database on the selected Paseo host in read-only mode. It recognizes V2 sessions and older SQLite databases. A database containing both uses V2 to avoid counting migrated sessions twice. No OpenCode server, VS Code extension, API key, or language model service is required.

Paseo 0.15.3 or later is required. The daemon needs Node's built-in SQLite support or the sqlite3 executable on its PATH. SQLite fallback was tested on macOS. Other operating systems have not been tested in a live host.

Provider settings let you enable, disable, select, or hide registered adapters and configure database paths. Discovery checks standard OpenCode data directories by default. An explicit path list replaces discovery. Only the OpenCode adapter is included; contributors can add other providers through the documented adapter contract.

The overview covers every matching session in the selected database and date window. It shows the three most frequent coaching priorities, counts and percentages, earlier/later period comparisons, a 14-day activity chart, and usage totals. Large histories are analyzed in the background with visible progress and warnings for unreadable or incomplete sessions. Results are provisional until analysis finishes. History supports date windows, exact workspace directory filters, and optional pagination for individual-session evidence. Coaching is deterministic and heuristic. A logged test command is evidence that verification was attempted, not proof it passed. Reports are limited to the first 2000 messages and 20000 legacy parts, with warnings for incomplete or invalid records.

Analysis runs on the daemon host. Up to four overview jobs and 1000 normalized reports are cached in memory and cleared on plugin reload; no copied conversations are persisted. Disabling a provider stops its background analysis before the next session read. Authorized Paseo clients receive session titles, directories, metrics, findings, and evidence IDs through Paseo's connection. The plugin has no outbound analytics or model requests, does not execute recorded commands, and does not modify session databases. As a trusted Paseo plugin, its code runs with the daemon's normal filesystem permissions.
